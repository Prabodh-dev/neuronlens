# Security policy

## Reporting a vulnerability

Report it through GitHub private vulnerability reporting: open the repository's **Security** tab and choose **Report a vulnerability**. Please do not open a public issue or pull request for it.

Include the version or commit, how to reproduce it, and what an attacker could do with it. You will get a reply on the report thread. If the report is valid, the fix is made privately and released before the details are published.

## Scope

In scope:

- the server in `server/` (request handling, path handling for `NEURONLENS_DB` and `NEURONLENS_CKPT`, SQL access, error responses);
- the web app in `web/`, for example script injection through text that comes from the API or from a shared link;
- the scripts in `ml/` and `server/scripts/`, for example unsafe handling of a database or checkpoint file;
- secrets committed to the repository.

Out of scope:

- running the server on an open network. See below.
- Denial of service through large or slow requests to a server that is exposed on purpose.
- Weaknesses in third-party packages that are not reachable through NeuronLens; report those upstream.
- Wrong or misleading feature labels. Labels are generated by a language model and are not checked by hand; open a normal issue.
- Checkpoints (`.pt` files) from untrusted sources. They are loaded with PyTorch and can run code; only load checkpoints you built or trust.

## The server has no authentication

The NeuronLens server has no login, no API keys and no rate limiting. It is meant to run on your own machine: `uvicorn` binds to 127.0.0.1 by default, and CORS allows only `http://localhost:3000` unless `NEURONLENS_CORS_ORIGINS` says otherwise. In real mode anyone who can reach the port can run the model on your GPU.

If you bind it to another address (`--host 0.0.0.0`) or put it behind a proxy, put authentication and limits in front of it yourself. Reports about the missing authentication itself are not treated as vulnerabilities.
